## 通用约定

### 服务地址与 context-path

- 后端端口 **8080**，`server.servlet.context-path = /api`（见 `hparty-admin/src/main/resources/application.yml`）。
- 因此所有接口的完整地址都要带 `/api` 前缀。例如登录接口：
  `http://localhost:8080/api/auth/login`
- 下文表格中的「路径」列均为 **不含 context-path** 的映射路径（与 Controller 注解一致），调用时请自行拼接 `/api`。

### 认证方式

- 请求头 `Authorization: Bearer <token>`（Sa-Token：`token-name=Authorization`，`token-prefix=Bearer`）。
- token 从 `POST /auth/login` 获取，默认有效期 7200 秒。
- 全局拦截器 `SaTokenConfig` 对 `/**` 强制登录，白名单（免登录）只有：
  `/auth/login`、`/auth/captcha`、`/auth/logout`、`/doc.html`、`/webjars/**`、
  `/v3/api-docs/**`、`/swagger-ui/**`、`/swagger-resources/**`、`/favicon.ico`、`/error`。
- 权限模型有两层：全局登录校验（拦截器）+ 细粒度权限/角色校验（`@SaCheckPermission` / `@SaCheckRole` 注解）。

### 统一响应体

```json
{ "code": 200, "msg": "操作成功", "data": {}, "timestamp": 1758000000000 }
```

- `code = 200` 为成功，其余均为失败。**HTTP 状态码恒为 200**，业务成败必须看响应体里的 `code`（`GlobalExceptionHandler` 未使用 `@ResponseStatus`）。
- 部分接口成功时 `msg` 是具体文案（如「登录成功」「新增成功」），不固定为「操作成功」。
- 全局 Jackson 配置 `default-property-inclusion: non_null`，但 `R` 类上有 `@JsonInclude(ALWAYS)`，因此 `data` 为 null 时字段依然存在。

### 业务错误码

| code | 含义 | 触发场景 |
|---|---|---|
| 200 | 成功 | |
| 400 | 参数校验失败 | `@Valid` 校验不通过、缺少必填参数、参数类型不匹配、请求体格式错误 |
| 401 | 未登录或登录已过期 | 未携带 token / token 无效 / token 超时 |
| 403 | 没有操作权限 | `@SaCheckPermission` / `@SaCheckRole` 校验不通过 |
| 404 | 资源不存在 | 常量定义，见 `ResultCode` |
| 405 | 请求方法不支持 | 例如用 GET 调用 POST 接口 |
| 500 | 系统错误 | 未捕获异常兜底 |
| **600** | **业务处理失败** | `BizException` 抛出的业务规则拦截（如「超级管理员角色不允许停用」） |
| **601** | **流程规则校验未通过** | 发展党员流程规则引擎不通过 |

600 与 601 的定义在 `hparty-common/src/main/java/com/hparty/common/core/ResultCode.java`。

### 分页

**分页响应结构**（`com.hparty.common.core.PageResult`）：

```json
{ "records": [], "total": 0, "current": 1, "size": 10, "pages": 0 }
```

**分页请求参数**（所有列表查询 DTO 继承 `com.hparty.common.core.PageQuery`，以 query 参数传递）：

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `pageNum` | int | 1 | 页码，从 1 开始，小于 1 时按 1 处理 |
| `pageSize` | int | 10 | 每页条数，小于 1 时按 10 处理，**上限 500**（超出被截断） |
| `orderByColumn` | string | 无 | 排序字段，下划线命名，需在白名单内 |
| `isAsc` | string | `desc` | 排序方向 `asc` / `desc` |

### 时间格式

- 日期：`yyyy-MM-dd`（`LocalDate`）。
- 时间：`yyyy-MM-dd HH:mm:ss`（`LocalDateTime`，实体上均显式标注了 `@JsonFormat`）。**仅在请求体（JSON）与响应中使用**。
- **作为 query 参数传递的 `LocalDateTime` 必须用 ISO 格式 `yyyy-MM-ddTHH:mm:ss`**（中间是字母 `T`）。用空格分隔会绑定失败并返回 `code=400`「参数类型不正确」。项目未注册自定义的 `Converter`/`@DateTimeFormat`，走的是 Spring 默认的 ISO 解析。
  - 目前唯一涉及 query 传时间的是 `/system/log/login/page` 与 `/system/log/oper/page` 的 `beginTime`、`endTime`。

### 「参数位置」列的含义

| 标注 | 含义 | 后端绑定方式 |
|---|---|---|
| `path` | 路径变量 | `@PathVariable` |
| `query` | URL 查询串 / 表单字段 | `@RequestParam` 或查询对象（`@ModelAttribute` 省略写法） |
| `body` | JSON 请求体 | `@RequestBody` |
| `form-data` | `multipart/form-data` 表单字段 | `@RequestParam` + `MultipartFile` |

多个位置用 `/` 分隔（如 `path/query`）。

## 一、登录鉴权 `/auth`（6 个）

Controller：`AuthController`，`@Tag(name = "01-登录鉴权")`，基础路径 `/auth`。

| 方法 | 路径 | 说明 | 权限 | 参数位置 | 返回 |
|---|---|---|---|---|---|
| GET | `/auth/captcha` | 获取图形验证码 | 免登录 | — | `R<CaptchaVO>` |
| POST | `/auth/login` | 账号密码登录 | 免登录 | body | `R<LoginVO>` |
| POST | `/auth/logout` | 退出登录 | 免登录 | — | `R<Void>` |
| **POST** | **`/auth/changePassword`** | **用户自助修改密码** | **仅需登录** | **body** | `R<Void>` |
| GET | `/auth/userInfo` | 获取当前登录用户信息 | 仅需登录 | — | `R<UserInfoVO>` |
| GET | `/auth/routers` | 获取动态路由菜单 | 仅需登录 | — | `R<List<RouterVO>>` |

**`POST /auth/changePassword` 说明**：body 为 `{oldPassword, newPassword}`。
必须原密码正确；新密码走 `PasswordPolicy` 强度校验（8-32 位、字母数字混合、
不在弱口令表内、不含账号名）；新旧密码不能相同。
**改完会强制下线当前会话**，需用新密码重新登录。

**`POST /auth/login` 新增三个响应字段**：`needChangePwd`（是否要求立即改密）、
`changePwdReason`（中文原因）、`passwordExpireDays`。两种情况会置 true：
从未改过初始密码（`pwd_update_date` 为空），或密码已超过
`hparty.password.expire-days`（默认 90 天）。

前端已实现对应处理：`src/pages/login/index.tsx` 在登录响应 `needChangePwd=true` 时
**不进入业务系统**，直接弹出 `src/components/ChangePasswordModal.tsx`
（强制模式，无取消按钮，只留「退出登录」一个出口），改密成功后本地清态、要求用新密码重登。

**关键字段说明**

- `GET /auth/captcha` 返回 `{ uuid, img, enabled }`。`img` 是 Base64 data URI，可直接放进 `<img src>`。`enabled=false` 时前端应隐藏验证码输入框。
- `POST /auth/login` 的 body（`LoginDTO`）：
  - `username` 必填（`@NotBlank`）
  - `password` 必填（`@NotBlank`，明文传输）
  - `code` 验证码，**当 `hparty.captcha.enabled=true`（当前配置为 true）时必填**
  - `uuid` 验证码会话标识，取自 `/auth/captcha` 的返回值
  - 连续登录失败会累加失败次数并锁定账号（Redis key `hparty:login:fail:`）。
- `POST /auth/login` 返回 `{ token, tokenName, expiresIn }`。`tokenName` 即请求头名（`Authorization`）。
- `/auth/logout` 在白名单内，因此**未登录状态下调用也不会报 401**。

### 2.1 用户管理 `/system/user`（7 个）

Controller：`SysUserController`，`@Tag(name = "用户管理")`，基础路径 `/system/user`。

| 方法 | 路径 | 说明 | 权限 | 参数位置 | 返回 |
|---|---|---|---|---|---|
| GET | `/system/user/list` | 用户列表 | `system:user:list` | query | `R<PageResult<SysUserVO>>` |
| GET | `/system/user/{userId}` | 用户详情 | `system:user:list` | path | `R<SysUserVO>` |
| POST | `/system/user` | 新增用户 | `system:user:add` | body | `R<Long>`（新增的用户 ID） |
| PUT | `/system/user` | 修改用户 | `system:user:edit` | body | `R<Void>` |
| DELETE | `/system/user/{userId}` | 删除用户 | `system:user:remove` | path | `R<Void>` |
| PUT | `/system/user/{userId}/password` | 重置密码 | `system:user:resetPwd` | **path/body** | `R<Void>` |
| PUT | `/system/user/{userId}/status` | 启用/停用用户 | `system:user:edit` | **path/query** | `R<Void>` |

**关键字段说明**

- 列表查询条件（`SysUserQuery`，全部走 query）：`username`、`nickName`、`phone`（三者模糊匹配）、`orgId`、`status`（0=停用 1=正常），加分页公共参数。列表已应用数据权限裁剪。
- 列表返回的 `SysUserVO` **包含 `roleNames`**（已分配角色名称，按 `role_sort` 排序；无角色时为 `[]`），供前端「角色」列直接展示；`roleIds` 仍只在详情接口返回，编辑弹窗回填用。超级管理员的 `orgId`/`orgName` 为 `null`，前端按「—」展示。
- 新增/修改 body（`SysUserDTO`）：`username`、`password`（**仅新增时使用**，服务端 BCrypt 加密）、`nickName`、`personId`（关联人员档案）、`orgId`、`phone`、`email`、`avatar`、`sex`（0=未知 1=男 2=女）、`status`、`remark`、`roleIds`（角色 ID 集合，**全量覆盖**）。修改时必传 `userId`。
  - 注意：该 DTO 上**没有加校验注解**，字段缺失由数据库约束兜底。
- `PUT /system/user/{userId}/password`：`userId` 在 path，**密码在 body**（`{"password": "xxx"}`，只用到 `password` 一个字段），走 body 是为了避免密码出现在 URL 中。
- `PUT /system/user/{userId}/status`：`status` 是 **query 参数**，即 `PUT /api/system/user/1/status?status=1`，body 传 `null`。
- 约束：超级管理员（userId=1）与当前登录账号不允许删除，也不允许停用。

- `GET /file/download/{fileId}`：必须登录，且文件归属组织需在当前用户数据权限内。返回字节流，`Content-Disposition: attachment`，原始文件名按 UTF-8 编码。

## 五、易错点汇总

以下均为**已经踩过或极易踩**的坑，接手时优先核对：

1. **`status` 是 query 参数，不是 body**
   - `PUT /api/system/user/{userId}/status?status=1`（body 传 `null`）
   - `PUT /api/system/role/{roleId}/status?status=1`（body 传 `null`）
   - 二者后端都是 `@RequestParam("status")`。

2. **`PUT /api/system/role/{roleId}/menus` 的 body 是纯数组**
   - 正确：`[1,2,3]`；错误：`{"menuIds":[1,2,3]}`。
   - 同样使用**纯数组** body 的还有：
     - `POST /api/party/meeting/{meetingId}/attendees`
     - `POST /api/party/election/{electionId}/candidates`
     - `POST /api/party/education/{activityId}/participants`
     - `POST /api/party/discipline/{studyId}/participants`
   - **例外**：`POST /api/party/excellent/candidate/batch` 用的是对象 `{selectionId, candidates:[...]}`，别混用。

3. **`/system/dept/list` 与 `/system/menu/list` 返回的是 `PageResult` 而不是数组**
   - 响应形如 `{records:[...], total, current, size, pages}`。前端已做兼容。
   - 需要树形结构请用 `/system/dept/tree`、`/system/menu/tree`（这两个才是 `List`）。

4. **`POST /api/party/dues/record/generate` 的 `year` / `month` 是 query 参数**
   - 正确：`POST /api/party/dues/record/generate?year=2026&month=9`（无 body）；错误：JSON body。
   - 两个参数都必填，缺一个会返回 `code=400`「缺少必填参数」。

5. **`POST /api/party/task/submit` 是 `multipart/form-data`**
   - 表单字段：`taskId`（必填），`file` / `fileId` / `fileUrl`（三选一，不能同时为空），另有可选的 `remark`。
   - 不要用 JSON 调用。只传 `fileId`/`fileUrl` 而漏掉 `file` 字段会导致文件被静默丢弃（接口仍返回成功，落库为 NULL）。

6. **`LocalDateTime` 作为 query 参数必须用 ISO 格式**
   - `2026-09-01T00:00:00`（`T` 分隔）；用空格 `2026-09-01 00:00:00` 会 400。
   - 涉及 `/system/log/login/page`、`/system/log/oper/page` 的 `beginTime` / `endTime`。
   - 但在 **JSON body 与响应**里，时间是 `yyyy-MM-dd HH:mm:ss`，日期是 `yyyy-MM-dd` —— 两套格式别弄混。

7. **`{ids}` 路径变量是逗号分隔的列表**
   - `DELETE /api/system/log/login/1,2,3`（`@PathVariable List<Long>`），不是数组 body，也不是重复 query 参数。

8. **`/file/preview/**` 与 `/file/download/**` 返回原始字节流，不是 `R` 结构**
   - 两者成功时都是字节流；鉴权/业务失败时仍可能返回 JSON `R`，Blob 调用方必须检查 `Content-Type`。
   - `/file/preview/**` 与 `/file/download/**` 都需要登录；preview 还会按 `sys_file.org_id` 做数据权限校验。
   - 前端预览走 `openFilePreview()` → Axios Blob → object URL，不再直接 `<img src=fileUrl>` / `<a href=fileUrl>`。

9. **权限注解存在 `mode = SaMode.OR` 的情况**
   - 触发条件：初始化脚本未预置对应按钮权限，为兼容而写成 OR。详见 2.5 字典管理、2.8 人员档案、3.4/3.5/3.6/3.9 中的写操作。
   - 例如 `@SaCheckPermission(value = {"system:dict:add", "system:dict:list"}, mode = SaMode.OR)` 表示**满足其中任意一个即可**，而不是两个都要。

10. **`/party/**` 写接口的权限已按动作拆分，不要再按「共用一个 `xxx:list`」理解**
    - `/party/meeting`：读 `meeting:list`；新增 `meeting:add`、修改会议与保存签到表 `meeting:edit`、删除 `meeting:remove`。
    - `/party/task`：读 `task:list`；发布 `task:add`、修改 `task:edit`、删除 `task:remove`、上传材料 `task:submit`。
    - `/party/material`：读 `orglife:list`；增 `orglife:add`、改 `orglife:edit`、删 `orglife:remove`。
    - 上述标识均已在 `sys_menu` 中种下，前端按 `can('meeting:edit')` 这类按钮级权限正常使用即可。

### 6.4 `/system/log/**` 的 `clean` 与 `{ids}` 路径存在潜在歧义（当前可正常工作）

同一个 Controller 内同时存在：

- `DELETE /system/log/login/{ids}`（`@PathVariable List<Long>`）与 `DELETE /system/log/login/clean`
