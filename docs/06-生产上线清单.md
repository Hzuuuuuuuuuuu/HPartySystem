### 1. ~~引入数据库版本管理~~ ✅ 已完成

已接入 **Flyway 9.22.3**，迁移脚本在 `hparty-admin/src/main/resources/db/migration/`：

| 文件 | 内容 |
|---|---|
| `V1__init_schema.sql` | 49 张表的建表语句 |

**两条路径都已实测验证**：

- **已有数据的老库**：`baseline-on-migrate: true` + `baseline-version: 2` 自动打基线，

  **不会重跑 V1/V2**（V1 含 `DROP TABLE`，重跑会清空数据），业务数据逐项核对无损

**今后加表 / 加列 / 改索引**：新建 `V3__描述.sql` 后启动即自动应用。
**已应用过的迁移文件不能再改** —— `validate-on-migrate: true` 会校验文件校验和，改了会导致启动失败，
要修正只能追加一个新迁移。

`sql/01-schema.sql` 与 `sql/02-init-system.sql` 现在只是**可读的参考副本**，不参与执行，
文件头已加显著标注。`sql/03-init-demo.sql`（演示数据）**不是迁移**，仍需手工执行，不要带进生产。

> 上线前记得确认：`spring.flyway.enabled` 在生产配置里保持 `true`
> （若在 `application-prod.yml` 里关掉它，整套版本管理就形同虚设）。

### 2. 强制修改默认密码 + 密码策略 ✅ 已完成

已实现，三处共用同一套规则与文案（`com.hparty.common.util.PasswordPolicy`）：

- **强度校验**：8-32 位、必须同时含字母和数字、不能是重复字符、
  不在弱口令表内（含本项目用过的 `12345678` 等）、不含连续序列（`12345678`/`abcdefgh`）、
  不能包含登录账号
- **首次登录强制改密**：`pwd_update_date` 为空即判定为「从未改过初始密码」，
  登录返回 `needChangePwd=true` + 中文原因，前端应弹强制改密对话框
- **密码过期**：超过 `hparty.password.expire-days`（默认 90 天）同样要求改密
- **用户自助改密**：新增 `POST /auth/changePassword`（此前**只有管理员能重置密码，
  用户自己改不了** —— 这是个明显的缺口）。必须验证原密码，改完强制下线

**生产默认密码闸门已完成**：V2 作为已发布迁移仍保留历史种子 `admin/123456`，但
`ProductionAdminBootstrap` 只在 `prod` profile 生效。生产启动时若检测到 admin 仍是该遗留
默认密码：

- 未设置 `HPARTY_ADMIN_INITIAL_PASSWORD` → **应用拒绝启动**；
- 环境变量不符合 `PasswordPolicy` → **应用拒绝启动**；
- 合法强口令 → 启动阶段立即 BCrypt 替换遗留密码，同时保持 `pwd_update_date=NULL`，
  因而首次登录仍会被现有机制强制改为个人密码；
- admin 已经改过密码 → 不要求该环境变量，也绝不覆盖现有密码。

部署时不要把 `HPARTY_ADMIN_INITIAL_PASSWORD` 写入仓库、YAML 或启动日志；只通过部署平台的
Secret/环境变量临时注入。首次登录并完成改密后即可从运行环境移除这个变量。

### 3. 启用 HTTPS

党务系统的数据敏感，明文 HTTP 不可接受。

- Nginx 前置，配置 TLS 证书，把 `/api` 反代到后端 8080
- 后端 `server.forward-headers-strategy: framework`（否则取不到真实客户端 IP）
- 开启 HSTS

### 6. 文件预览鉴权（已完成）

`/file/preview/**` 已从 `SaTokenConfig.WHITE_LIST` 移除，预览 URL **不再等同于访问凭证**。当前安全边界为：

- 必须携带有效 `Authorization: Bearer <token>`；
- 后端必须先找到有效 `sys_file` 元数据，磁盘孤儿文件不允许直接读取；
- `sys_file.org_id` 不为空时，按当前用户数据范围执行组织权限校验；
- 路径分段校验与 `FileStorage` 路径规范化继续保留；
- 前端使用 `openFilePreview()` 经 Axios 获取 Blob，再用 object URL 展示，不把 token 放进 URL。

**上线检查**：不要在 Nginx/网关层把 `/api/file/preview/**` 改成直接静态文件映射，否则会绕过 Spring 登录校验与数据权限。若未来业务必须用 `<img>` / `<video>` 直接引用文件地址，应采用鉴权 Blob/object URL，或单独设计带过期时间与 HMAC 的短时签名 URL；不要重新加入匿名白名单。

## P1 — 强烈建议

### 7. 令牌存储方式

前端把 token 存在 `localStorage`（`src/api/request.ts` 的 `TOKEN_KEY`）。
一旦有 XSS 漏洞，token 可被直接读取。

**改进方向**：
- 后端改为把 token 写入 **httpOnly + Secure + SameSite 的 Cookie**，前端不再接触 token
- 或者：保持 localStorage，但把有效期从 2 小时缩短，并实现 refresh token 机制
- 无论哪种，都要做完整的 XSS 防护（输出转义、CSP 头）

### 8. 接口限流

目前**没有任何限流**。登录接口只有「连续失败 5 次锁定」这一层保护，
但验证码接口本身可被刷（每次请求都会生成一张图并写 Redis）。

**怎么做**：引入 Sentinel 或用 Redis + 拦截器实现简单限流：
- `/auth/captcha`：按 IP 限流（如 10 次/分钟）
- `/auth/login`：按 IP + 账号限流
- 全局：按用户限流（如 100 次/分钟）

### 9. 敏感个人信息保护

`party_person` 存了身份证号、手机号、出生日期、家庭情况（政治审查材料里还有亲属政治情况）。
这些属于《个人信息保护法》下的**敏感个人信息**。

**必须做的**：
- 列表页身份证号**脱敏显示**（`410102********0024`），完整值仅在有权限的详情页可见
- 导出功能（`docs/07-扩展模块说明.md` 里的报表导出）要对敏感字段做权限控制并留痕
- 数据访问审计：谁在什么时候查了谁的完整身份证号，应当可追溯
- 数据库层面考虑对 `id_card` 加密存储（当前是明文）

### 10. 补全操作日志覆盖

`@OperLog` 目前只挂在**发展党员办理、用户管理、角色管理**上。
其余模块（党费、换届、教育、党纪、服务、评选、三会一课）的写操作都没有留痕。

**党务系统的操作留痕是硬要求** —— 谁改了党费金额、谁删了会议记录，都必须可查。
建议逐个 Controller 的写方法补上 `@OperLog`，并考虑实现
`docs/07-扩展模块说明.md` 里提到的日志归档策略（日志表会持续增长）。

### 11. 定时任务 ✅ 已完成

实现在 `com.hparty.job.HPartyScheduledTasks`（启动模块，因为要同时注入
system / party / develop 三个域的服务）。`@EnableScheduling` 已开启。

| 任务 | 默认时间 | 说明 |
|---|---|---|
| 党费账单生成 | 每月 1 日 01:07 | 调 `PartyDuesService.generate`，按「人+年+月」幂等 |
| 超期扫描 | 每日 07:23 | 三类一起扫：发展党员待办步骤、党费欠缴、转接超期 |
| 日志清理 | 每日 03:13 | `SysLogService.cleanBefore`，保留 `log-retain-days`（默认 90 天） |

- 时间一律**错开到非整点**，避免与其他系统撞在同一秒
- 全部幂等，手动补跑、重启重跑、多实例并发都不会产生重复数据
- 每个任务内部 **catch 所有异常并记录** —— 抛出去只会让调度线程静默失败，
  Spring 默认还会取消该任务的后续调度
- `hparty.job.enabled=false` 可整体关闭（本地调试/单测时有用）
- cron 表达式全部可在配置里覆盖，`application-prod.yml` 里已给出生产值

**尚未加入的**：预备期满临近提醒（需要通知渠道，见下）。
目前只有「记录到日志」，**没有对外通知** —— 真要起到预警作用，
需要有站内消息或短信/邮件通道，那是另一块工作。

### 12. 补单元测试（尤其是流程引擎）

**这是当前最大的质量风险。** `hparty-develop` 的 8 条规则有十几种日期推算与票数判定，
全靠人工点。此前一轮审计发现的 14 个缺陷里有 3 个出在该模块，包括一个
「流程卡死在第 13 步」的致命 bug —— 它被演示数据预填的日期掩盖了很久。

**优先补这些用例**：

| 规则 | 必须覆盖的边界 |
|---|---|
| `IntervalRule` | 恰好满 365 天 / 差 1 天；周期性步骤 `advance=false` 时不校验 |
| `VoteRule` | 应到 15 人时需 8 人（而非 7.5）；赞成票分母是**应到**不是实到；票数合计超实到人数 |
| `ProbationPeriodRule` | 延长 6 个月后 12 个月内的推进被拒；延长 2 次被拒 |
| `BranchRule` | 延长 5 个月被拒、13 个月被拒、第 2 次延长被拒 |
| `DeadlineRule` | 超期只 WARN 不 REJECT |
| `TrainingHourRule` | 恰好 3 天 / 恰好 24 学时（满足其一即可） |

`DevContext` 已预留 `now` 字段用于注入固定时间，`DevContext.builder()` 便于构造上下文。

## P2 — 有余力再做

### 13. 监控与告警
- Spring Boot Actuator 暴露健康检查，接入 Prometheus + Grafana
- 关键告警：接口 5xx 率、数据库连接池耗尽、Redis 不可用、磁盘空间（文件存储会持续增长）

### 14. 前端构建优化
- 目前 `manualChunks` 已把 react / antd 分包，但 antd 全量引入，体积偏大
- 生产构建前确认 `npm run build` 产物正常，并用 Nginx 托管 `dist/`（不要用 `npm run dev`）

### 15. 字典缓存改造
`SysDictTypeService` 用的是**单机 JVM 内缓存**（`ConcurrentHashMap`）。
多实例部署时，一个实例改了字典，其他实例不会失效。需改为 Redis 缓存。

### 16. 已知的功能性遗留

| 项 | 说明 |
|---|---|
| `sys_dept.member_count` | 冗余列，人员增减后**不会自动更新**。要么加维护逻辑，要么废弃该列改实时统计 |
| `data_scope=5`（自定义） | 已通过 `sys_role_dept` 做按 ID 权限校验；列表过滤与详情/修改/删除的权限口径已统一 |
| 候选人/参学名单 | 全部是全量数组返回、不分页，数据量大时需改分页或虚拟滚动 |
| 列表页排序 | 前端未提供排序交互，后端 `PageUtils.applyOrder` 已支持 |
